# penquins.software

Сайт команды **Penquins Software**: каталог игр, страницы проектов, скриншоты и ссылки на itch.io.

Статический сайт на [Astro](https://astro.build). Без бэкенда: всё собирается в HTML и CSS и отдаётся с GitHub Pages. Клиентского JS немного — только случайный порядок на главной и фильтры каталога.

Нужен Node.js **22.23.4** или новее (требование Astro 7).

## Локальный запуск

```bash
npm install
npm run dev
```

Сборка и предпросмотр:

```bash
npm run build
npm run preview
```

Проверка типов:

```bash
npm run check
```

```

  components/            — шапка, подвал, карточка игры, бегущая строка
  pages/
    index.astro          — главная
    games/index.astro    — каталог
    games/[slug].astro   — страница игры
    about.astro          — о команде

    robots.txt.ts
  styles/global.css      — дизайн-система и все стили
public/
  covers/                — обложки игр (WebP)
  shots/                 — скриншоты (WebP)
  logo.png               — логотип команды
  penguin.png            — маскот

  og.jpg                 — превью для соцсетей (1200×630)
  og/                    — отдельные превью для страниц игр
  games/                 — сюда кладутся локальные веб-сборки игр
```

## Как изменить или добавить игру

1. Откройте `src/data/games.ts`.
2. Добавьте объект в массив `games` (или отредактируйте существующий).
3. Положите обложку в `public/covers/<slug>.webp`, скриншоты — в `public/shots/`.
4. Сделайте превью для соцсетей `public/og/<slug>.jpg` (1200×630) — оно подставляется в `og:image` страницы игры.
5. Для игры в браузере укажите `browser: true` и ссылку на itch.io.
6. Порядок в массиве `games` = порядок в каталоге: сверху новые игры, как в профиле на itch.io. Новую игру добавляйте в начало массива.
7. Избранное на главной задаётся массивом `featuredSlugs` — порядок слогов в нём же определяет порядок карточек.
8. Если у игры есть страница на VK Play, добавьте `vkPlayUrl` — рядом с кнопкой itch.io появится вторая кнопка.
9. Если в `credits` появился новый участник, добавьте ссылку на его itch-профиль в `memberProfiles` — там же, в `src/data/games.ts`.

Страница игры и карточка в каталоге создадутся автоматически.

## Фильтры и бегущие строки

Каталог умеет фильтроваться по жанру и автору. Состояние хранится в адресе страницы, ссылки можно шарить:

```
/games/?genre=Экшен
/games/?author=Oz%20Fox
```

На главной бегущая строка показывает жанры. Порядок перемешивается при каждой загрузке страницы (маленький инлайновый скрипт), а сами подписи — ссылки на каталог с нужным фильтром. Строка декоративная и скрыта от скринридеров: те же фильтры доступны кнопками на странице «Игры».

Случайные обложки в шапке главной выбираются из всех игр при открытии страницы.

## Веб-сборки игр

1. Соберите игру под веб (Unity WebGL, Godot HTML5, GameMaker, Ren'Py и т.д.).
2. Положите сборку в `public/games/<slug>/play/` так, чтобы открывался `public/games/<slug>/play/index.html`.
3. В `src/data/games.ts` добавьте игре поле:

```ts
playUrl: "/games/<slug>/play/",
```

Кнопка на странице игры начнёт вести на локальную версию, а ссылка на itch.io останется как запасная.

Важно:

- пути внутри сборки должны быть **относительными**, чтобы она не зависела от адреса страницы;
- на GitHub Pages нельзя задавать HTTP-заголовки. Для **Unity WebGL** включите Decompression Fallback (или Gzip), для **Godot 4** отключите Thread Support либо добавьте `coi-serviceworker.js`;
- один файл в репозитории — не больше 100 МБ, весь опубликованный сайт — не больше 1 ГБ;
- тяжёлые сборки (больше ~50–100 МБ) лучше держать на itch.io, а здесь оставить страницу и ссылку.

## Деплой на GitHub Pages

Сайт рассчитан на **корень домена**: `https://<account>.github.io/` или собственный домен. Поэтому репозиторий должен называться `<account>.github.io` — сейчас это `thepenquins.github.io`, сайт живёт на `https://thepenquins.github.io/`.

1. Создайте репозиторий `<account>.github.io` и запушьте туда проект.
2. В **Settings → Pages → Build and deployment** выберите **GitHub Actions**.
3. Запушьте в `main` — workflow `.github/workflows/deploy.yml` соберёт и опубликует сайт.
4. Через пару минут сайт будет доступен по адресу `https://<account>.github.io/`.

Если репозиторий называется иначе, сайт окажется в подпапке `/<repo>/`, и абсолютные пути (`/covers/...`) сломаются. В этом случае проще переименовать репозиторий или подключить домен.

### Свой домен

1. В **Settings → Pages → Custom domain** укажите `penquins.software`.
2. У регистратора добавьте DNS-записи:
   - `A` для apex-домена на IP GitHub Pages (`185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`);
   - `CNAME` для `www` на `<account>.github.io` (`thepenquins.github.io`).
3. Включите **Enforce HTTPS**.
4. Соберите сайт с нужным адресом: `SITE_URL=https://penquins.software npm run build`. Это меняет canonical, `og:url`, `sitemap` и `robots.txt`; без переменной используется `https://thepenquins.github.io`.

## Что важно помнить про GitHub Pages

- только статика: нет серверного кода, базы данных и авторизации;
- опубликованный сайт — до 1 ГБ, трафик — ~100 ГБ/мес (мягкий лимит);
- файл в репозитории — до 100 МБ, Git LFS для Pages не работает;
- свои HTTP-заголовки, редиректы и `.htaccess` недоступны;
- сайт всегда публичный, даже если репозиторий приватный;
- коммерческие продажи и 18+ контент — не для GitHub Pages; для этого есть itch.io.
